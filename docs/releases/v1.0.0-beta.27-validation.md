# Validação da Beta 27 — 12/11/2026

Release público: https://github.com/talismanbruno/lumesync/releases/tag/v1.0.0-beta.27

## Resultado e causa
O Windows sinaliza movimento reduzido neste computador. Avatar usava essa preferência tanto na imagem de perfil quanto na seleção da moldura, carregando /static mesmo com a moldura habilitada. A prova nativa anterior confirmou esse comportamento. Os assets originais do catálogo são APNGs de 60 frames, apesar da extensão .png, e chegam intactos da produção.

AvatarDecoration usa ImageDecoder no Electron/Chromium para reproduzir os frames e tempos originais. A moldura permanece visível no silêncio, preserva o último frame e retoma quando o SpeakingDetector marca atividade real do áudio. A histerese existente de 250 ms evita alternância entre pausas pequenas. Perfis abertos reproduzem a mídia original. O decoder fecha após 1,5 s em pausa; frames individuais fecham após pintar, e fechar o perfil aborta downloads e libera timers/decoder. Eventos nativos de visibilidade suspendem janelas ocultas, inclusive durante chamadas com backgroundThrottling desativado. Browsers sem ImageDecoder usam o asset animado nativo durante reprodução e o estático no silêncio.

A revisão identificou também recarga automática pelo service worker, independente do bloqueio visual de chamadas. A correção web posterior ao instalador usa confirmação no navegador, bloqueada durante chamadas/uploads, e remove o worker do Lume no Desktop para manter somente seu aviso nativo. O timer de verificação web é liberado ao desmontar. A API de instância passou a obter a versão do package.json, eliminando a antiga constante beta.19.

## Atualizador real
Windows usa Electron 43.4.0, electron-updater e instaladores NSIS. A fonte fica fixada no repositório oficial talismanbruno/lumesync, com SemVer superior, sem downgrade, manifests beta/latest e SHA-512 verificado pelo downloader. A interface mostra versão instalada por app.getVersion(), progresso e erro real. Instalação ao sair está desabilitada. Atualizar e reiniciar chama quitAndInstall(true, true) somente com download pronto e sem chamada ativa. O temporizador que poderia abrir o executável antigo foi removido. O diretório de dados e as sessões não são removidos pelo fluxo.

## Execução comprovada
- O script packages/desktop/scripts/avatar-animation-smoke.cjs usa os componentes React e o preload reais, com dois APNGs originais. Comprovou mudança de pixels em ambos, frames idênticos ao pausar, nenhum decode no silêncio, fechamento dos decoders, desmontagem do perfil, retomada, suspensão ao ocultar a janela nativa e retomada ao exibir.
- Amostra curta do renderer isolado: aproximadamente 111 MiB de working set. Não é prova de ausência de vazamento em sessões longas ou do consumo total de uma chamada.
- Executável Windows empacotado confirmou versão 1.0.0-beta.27 e suporte a updates. O botão real das configurações consultou o GitHub e mostrou Você está usando a versão mais recente. Uma conexão bloqueada no processo isolado exibiu net::ERR_PROXY_CONNECTION_FAILED e manteve o botão funcional.
- A Beta 26 oficial foi baixada com SHA-512 conferido, extraída sem instalação e executada com perfil/cache isolados. Ela detectou a Beta 27 pública, baixou o instalador x64 real, recebeu 7 eventos de progresso e exibiu Atualizar e reiniciar no painel e no aviso. O SHA-512 e tamanho do download coincidem com beta.yml. O cliente isolado foi encerrado sem executar o instalador.
- Os 28 arquivos públicos responderam HTTP 200 com tamanho correto. A tag v1.0.0-beta.27 aponta para 8ad336011d6607f0bc39f2fecb33a7611b60224f. Beta 26 mantém seu ID e seus 28 arquivos anteriores.

## Limitações e pendências reais
- Não foi executada instalação sobre o Lume existente, que está em uma pasta fora das áreas graváveis desta execução. Portanto, troca pelo NSIS, reabertura com a nova versão e preservação de sessão autenticada após upgrade não estão comprovadas. A instalação existente permaneceu na Beta 26 durante a checagem; os testes usaram perfis isolados.
- Não houve chamada real entre duas contas com microfone/câmera físicos nem validação completa de envio/abertura/download de arquivos pela interface. Os auxiliares de interface do Windows falharam na inicialização. As suítes cobrem esses contratos, mas não substituem essa validação.
- macOS/Linux têm download manual; Windows não tem certificado de publisher configurado. HTTPS/checksum não são assinatura de código.
- O backup local antes da implantação foi criado. O hook de cópia para Oracle Object Storage falhou porque a PAR configurada não atende ao formato de bucket gravável esperado. A credencial não foi alterada nem exposta; corrigir esse backup remoto requer uma PAR válida. Isso não é uma falha do atualizador.
